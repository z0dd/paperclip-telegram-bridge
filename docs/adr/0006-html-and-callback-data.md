# ADR-0006. HTML parse mode и схема callback_data `v1:…`

- Статус: принято; **частично заменено [ADR-0010](0010-v2-forum-bridge.md)** (v2.0.0):
  - заменено: схема `callback_data` и проверка нажатий (в v2 кнопок нет, `callback_query` не запрашивается); правило «Markdown из Paperclip не интерпретируется» — в v2 Markdown ответа агента превращается в Telegram HTML (`render/markdown.rs`), текст по-прежнему экранируется, теги ставит только рендер; статическая часть карточки и клавиатура;
  - остаётся в силе: `parse_mode=HTML` и экранирование, нарезка на куски ≤ 3500 UTF-16 единиц, `MAX_MESSAGE_CHUNKS` с пометкой об обрезке

## Контекст

Ошибка экранирования в Telegram — это `400` и потерянное сообщение. `callback_data` ограничен 64 байтами и виден клиенту.

## Решение

- `parse_mode=HTML`: экранируются только `&`, `<`, `>` и `"`. Весь текст из Paperclip выводится как обычный текст; теги ставят только шаблоны bridge.
- Сырой текст режется до экранирования на куски ≤ 3500 UTF-16 единиц по границам `\n\n` → `\n` → пробел → жёстко, без разрыва суррогатных пар. Кусков не больше `MAX_MESSAGE_CHUNKS`, иначе последний заканчивается «…полный текст — в Paperclip». Статическая часть карточки не зависит от состояния, поэтому число сообщений не меняется между правками; клавиатура — у последнего.
- `callback_data`: `v1:<op>:<did>:<gen>[:<a>[:<b>]]`, ASCII, base36. `did` — id доставки в state, `gen` — поколение клавиатуры, `a`/`b` — индексы. Идентификаторов Paperclip и текста в нём нет. Операции: `ac rj o t nx bk tx sb ed cn va vr vd vA gc gx nr` (`nr` — «Без причины»).
- Каждое нажатие проверяется по state: доставка существует и открыта, `gen` текущий, индексы в пределах snapshot. Иначе — «Устарело» и перерисовка.

## Последствия

- Максимальная длина `callback_data` для `i64`/`u32` — 47 байт.
- Markdown из Paperclip не интерпретируется.

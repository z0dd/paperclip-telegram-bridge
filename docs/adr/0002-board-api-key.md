# ADR-0002. Board API key как учётные данные bridge

- Статус: принято (решение пользователя: бессрочный ключ основного пользователя)
- Контекст: [docs/paperclip-api.md](../paperclip-api.md) §2
- Дополнено [ADR-0010](0010-v2-forum-bridge.md) (v2.0.0): ключ действует во всех компаниях пользователя (§1.1), допускается список ключей одного пользователя (`PAPERCLIP_TOKEN_FILES`). Перечень операций заменён: bridge v2 читает беседы и комментарии и **публикует комментарии** в беседы (см. [PAPERCLIP_PERMISSIONS](../PAPERCLIP_PERMISSIONS.md)); «ключ отклонён» — только `401`, `403` относится к компании или беседе. Остаются в силе: board key, хранение в файле как `SecretString`, бессрочность, отзыв

## Контекст

Agent key и agent JWT не могут отвечать на карточки `human_only` и не видят company-wide ленту `attention`. Сузить board key по scope нельзя: он несёт полный доступ своего пользователя.

## Решение

- Bridge работает с board API key (`pcp_board_…`) пользователя, который отвечает на вопросы. Ключ читается только из файла `PAPERCLIP_TOKEN_FILE` и хранится как `SecretString`.
- Ключ бессрочный (`expiresAt: null`). Основная мера защиты — быстрый отзыв: UI, `DELETE /api/board-api-keys/{keyId}` или подкоманда `bridge revoke-paperclip-key` (`POST /api/cli-auth/revoke-current` тем же ключом).
- Bridge вызывает только операции из перечня в контракте (лента, карточки, ответы, задачи и runs для команд, formal approval для destructive-действий). Комментарии, создание задач, endpoints секретов и посторонние approvals не вызываются.

## Последствия

- Компрометация контейнера даёт атакующему права пользователя до отзыва ключа (остаточный риск №1, принят пользователем).
- Ключа нет ни в state, ни в его backup.
- `401`/`403` переводят bridge в состояние «ключ отклонён»: одно сообщение пользователю, healthcheck unhealthy, повтор раз в 5 минут.
